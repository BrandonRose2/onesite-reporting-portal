## Observed checklist structure

The reference checklist is a **manager working document**, not just a property directory row. It is organized as a guided follow-up packet with these major sections:

1. **Header / working context**
   - Property name and title: `Manager Delinquency & Availability Checklist`
   - Confidential manager-working-document note
   - Explicit cross-reference to the property ID, availability PDF, and delinquency ledger

2. **Call details**
   - Availability report as-of date
   - Manager contacted: checkbox choices for `Yes`, `Voicemail`, `Follow-up required`
   - Manager name
   - Call date / time
   - Next commitment date

3. **Source cross-reference**
   - Availability PDF filename
   - Delinquency spreadsheet filename(s)
   - Spreadsheet comparison note
   - Ledger accounts for review count
   - Residents with amount owed count
   - Prepaid / credit accounts count
   - Availability entries count

4. **Availability follow-up**
   - Checklist items for status confirmation, make-ready / target date, leasing / move-in commitment, and escalation
   - Unit-by-unit table with:
     - Unit
     - Floor plan
     - Reported status
     - Manager verification
     - Follow-up / target date

5. **Resident balance follow-up — amount owed**
   - Priority guidance line for calling / confirming payment status
   - Resident table with:
     - Unit
     - Resident
     - Ledger status
     - Prepaid / credit
     - Owed
     - 90+ days
     - Manager follow-up checkboxes: `Contacted`, `Arrangement`, `Escalate`
     - Notes

6. **Resident balance follow-up — prepaid / credit**
   - Separate resident table for prepaid / credit accounts
   - Follow-up action is `Confirm paid`

7. **Resident balance follow-up — paid / zero balance**
   - Present as its own closing section
   - In the reviewed sample: `No resident ledger entries were detected in the selected source export.`

8. **Manager summary & commitments**
   - Availability status / blockers
   - Reviewed with manager checkbox
   - Notes field
   - Delinquency commitments / payment arrangements
   - Escalations requiring regional or corporate support
   - `None` checkbox and `Escalation required` field
   - Next manager follow-up date

9. **Closing note**
   - Generated from the property's supplied Availability PDF and delinquency spreadsheet(s)
   - Manager must validate operational status before acting on any resident account

## Design implications for portal redesign

- The current portal should emphasize **opening a property-specific checklist workspace**, not only listing properties.
- The checklist experience should surface:
  - Call details at the top
  - Source cross-reference context
  - Availability follow-up table
  - Resident balance follow-up table(s)
  - A manager summary / commitments section
- The workflow should feel like a **fillable review document** rather than a generic analytics dashboard.
- The portal should preserve the user's instruction that delinquency presentation stays current-resident-focused, while still matching the PDF's practical follow-up structure.
